What Kurly is for

Kurly is a desktop app for working with curl commands: the one-line recipes for calling a web API that you find in API documentation, bug reports, chat messages and your browser's developer tools.

curl is powerful, but its commands are hard to read and easy to get wrong: dozens of options, careful quoting, long lines. Kurly turns a request into a form you can read at a glance, and keeps the matching command in sync as you edit. Use it to:

  • Build a command without memorizing curl's options, then copy it into a terminal, a script or documentation.
  • Understand a command someone sent you: import it and see the URL, headers and body laid out in a form.
  • Try an API: run the request and read the response, with JSON and XML neatly indented.
  • Keep the requests you use often in a library, so they're one click away next time.

Kurly runs on macOS, Windows and Linux, in English and Japanese. It's free and open source.

What is curl?

curl is a free command-line program for sending requests to servers and printing what comes back. It has been around since 1998, speaks many protocols (most often HTTP and HTTPS, the protocols of the web), and is installed on macOS, Windows 10 and later, and almost every Linux system. Because it's everywhere, a curl command has become the standard way to show exactly how to call an API.

Kurly doesn't replace curl: it uses the curl already on your computer to run requests, and the commands it shows are real curl commands you can run anywhere.

Requests and responses

Talking to a web API is a conversation of requests and responses. Your request says what you want; the server's response says what happened.

A request has:

  • a URL: where to send it, such as https://api.example.com/v1/users/42. Anything after a ? is the query string, extra parameters like ?page=2;
  • a method: what to do (see below);
  • headers: extra information as Name: value pairs, such as the format you want back (Accept: application/json) or your credentials (Authorization: Bearer …);
  • sometimes a body: data to send, often JSON, when creating or changing something.
MethodUsually means
GETFetch something. The default.
POSTSend data, often to create something new.
PUTReplace something with the data you send.
PATCHChange part of something.
DELETERemove something.
HEADLike GET, but only the response headers, without the body.
OPTIONSAsk what the server allows.

A response has a status code, headers and usually a body. The status code's first digit tells you how it went: 2xx success (200 OK, 201 Created), 3xx look elsewhere (a redirect), 4xx a problem with the request (401 Unauthorized, 404 Not Found), 5xx a problem on the server.

Good to know: to curl, a 404 or 500 response is still a successful conversation. It only reports an error if it couldn't talk to the server at all, unless you use the -f option (Fail on HTTP errors in Kurly).

Reading a curl command

Here is a typical command, as you might find it in API documentation:

curl -X POST 'https://api.example.com/v1/users' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer YOUR_TOKEN' \
  --data-raw '{"name": "Hanako Yamada"}'
  • curl runs the program; everything after it is options and the URL.
  • -X POST sets the method. Without it, curl uses GET, or POST when there's a body, so Kurly leaves -X POST out in that case.
  • 'https://…/users' is the URL.
  • Each -H adds a header.
  • --data-raw is the body, sent exactly as written.
  • The \ at the end of a line means "the command continues on the next line".
  • The single quotes '…' keep the shell from treating characters like &, ?, $ or spaces specially. A quote inside a quoted value is written '\''.

Most options have a short and a long name, such as -H and --header; they mean the same. Kurly can show either (see The command).

Getting started

Installing

Download Kurly for your system from the download section:

  • macOS: open the .dmg and drag Kurly into Applications. The first time, macOS may say it can't check the app; allow it under System Settings → Privacy & Security → Open Anyway.
  • Windows: unzip the .zip and run Kurly.exe; there's nothing to install. If SmartScreen appears, choose More info → Run anyway.
  • Linux: make the AppImage executable with chmod +x Kurly-*.AppImage and run it. On Arch Linux you can also build a package.

Kurly uses your system's curl to run requests. It's already installed on macOS, Windows 10 (version 1803) and later, and nearly every Linux distribution.

Your first request

  1. Open Kurly and type https://httpbin.org/get into URL. httpbin.org is a free test service that replies with a description of the request it received.
  2. The command on the right reads curl https://httpbin.org/get.
  3. Press Run (Ctrl/⌘+Return). The response appears below the command, and the status line shows Done and how long it took.
  4. Add a header, for example X-Hello with the value world, and run it again: httpbin's reply now includes your header.

Using Kurly

The window

Kurly's window has up to three columns, separated by dividers you can drag:

  • Library (optional, on the left): your saved requests. Hidden until you click Library.
  • The form (middle): everything about the request. It scrolls when the window is small.
  • Command and response (right): the curl command at the top, and the response of the last run below it.

Building a request

  • URL and Method: where to send the request and what to do (see Requests and responses). Choosing HEAD uses curl's -I option.
  • Headers: one header per row, with its name and value. Click Add header for another row; select rows and click Remove selected to delete them. Rows without a name are ignored.
  • Request body: the data to send. It's sent exactly as typed (--data-raw), so remember the matching Content-Type header, such as application/json, and a method that takes a body, usually POST, PUT or PATCH.
  • User: user:password for servers that use basic authentication.
  • User agent: replaces the name curl sends to identify itself.
  • Timeout: how many seconds to wait before giving up; None waits as long as it takes.
  • Save output to file: writes the response body to a file instead of showing it. When you run the request from Kurly, a relative path like out.json is saved in your home folder (in the Flatpak version, in your Downloads folder).
  • Options: the checkboxes for common curl options, listed in Common options.

The command

The command at the top right always matches the form. Click Copy command to put it on the clipboard, ready to paste into a terminal, a script or documentation. Two checkboxes change how it's written, without changing what it does:

  • Use long option names: --header instead of -H, easier to read in documentation.
  • Split across multiple lines: one option per line, joined with \.

Kurly remembers both choices. Commands are quoted for macOS and Linux shells (bash, zsh), and also work in Git Bash and WSL on Windows. For PowerShell, see Troubleshooting.

Running a request

Click Run (Ctrl/⌘+Return, which also works while typing in the body) to send the request with your curl. While it runs, the button becomes Stop.

The response pane shows everything curl printed: the response body, and also response headers or the verbose log if you turned those options on. When a complete JSON or XML response arrives, it's shown indented, with keys in their original order; untick Format JSON/XML to see it exactly as received. Very large responses are cut off after about two million characters, marked [Output truncated]; use Save output to file for those.

The status line says how the run ended:

Importing a command

Click Import curl command… (Ctrl/⌘+Shift+I) and paste a command to fill in the form. If there's already a curl command on your clipboard, it's filled in for you.

To copy any request your browser makes, open its developer tools (F12, or ⌥+⌘+I on a Mac), go to the Network tab, reload the page, then right-click a request:

  • Chrome, Edge: Copy → Copy as cURL (bash), or Copy as cURL (cmd) on Windows.
  • Firefox: Copy Value → Copy as cURL.
  • Safari: Copy as cURL. (Turn on Show features for web developers in Safari's Advanced settings first.)

Both the bash format and the Windows cmd format work. A few things are adjusted on import: cookies given with -b become a Cookie header, -e becomes a Referer header, and --json sets the body and the JSON headers. Options Kurly can't represent, such as --proxy or file uploads (-F), are listed after the import and left out.

When the library is open, an imported command becomes a new request, unless the current one is still empty, so imports never overwrite a saved request. With the library hidden, the import replaces the current request.

Saving requests

Kurly 0.2 and later

Kurly saves your work automatically: close it, and your request is there next time. To keep several requests, click Library (Ctrl/⌘+B) to show the list of saved requests. Click a request to open it; each one keeps its own response, and a request that's still running carries on in the background while you look at another.

  • New (Ctrl/⌘+N) adds an empty request; Duplicate copies the selected one.
  • Rename a request by double-clicking it or pressing F2. Requests without a name are shown as their method and address, like GET api.example.com/v1/users; clear a name to go back to that.
  • Delete (or the Delete key, ⌫ on a Mac) removes the selected request after asking.
  • Drag requests to reorder them, and type in the box above the list to filter by name or URL.
  • Right-click a request for the same actions.

The library is stored in a file called library.json, in Kurly's folder for app data:

SystemFolder
macOS~/Library/Application Support/Bekind Labs/Kurly/
Windows%APPDATA%\Bekind Labs\Kurly\
Linux~/.local/share/Bekind Labs/Kurly/
Linux (Flatpak)~/.var/app/io.github.Bekind_Labs.Kurly/data/Bekind Labs/Kurly/

About passwords and tokens: requests can contain credentials, such as an Authorization header or a User password. They're saved as plain text, in a file only your user account can read. Avoid saving secrets you wouldn't keep in a file on your computer.

Troubleshooting

"Could not start curl"
Kurly couldn't find the curl program. Install it with your system's package manager (for example sudo apt install curl), then restart Kurly.
macOS says Kurly can't be opened or checked
Kurly isn't notarized by Apple yet. Open System Settings → Privacy & Security and click Open Anyway next to the message about Kurly. You only need to do this once.
Windows shows "Windows protected your PC"
Choose More info → Run anyway. SmartScreen shows this for apps it hasn't seen often.
The AppImage doesn't start on Linux
Make sure it's executable (chmod +x Kurly-*.AppImage). AppImages also need FUSE 2, which newer Ubuntu releases don't install by default: install libfuse2 (libfuse2t64 on Ubuntu 24.04), or run the AppImage with --appimage-extract-and-run.
A copied command doesn't work in PowerShell
In Windows PowerShell, curl is a different command (an alias for Invoke-WebRequest); type curl.exe instead. Also turn off Split across multiple lines, since PowerShell doesn't use \ to continue lines. Commands are easiest to use in Git Bash or WSL.
Requests need to go through a proxy
curl uses the standard proxy environment variables, such as HTTPS_PROXY and NO_PROXY. Set them for your session before starting Kurly, and its requests use them too.
Kurly says the library was damaged
Kurly couldn't read library.json, so it started a new library and kept the old file next to it as library.json.corrupt-…, so nothing is lost.
"This plugin supports grabbing the mouse only for popup windows"
A harmless note Qt prints in the terminal on Wayland desktops. Nothing is wrong.

Something else? Report a problem on GitHub.

Privacy

Kurly has no account and no tracking. It only connects to the network when you run a request, and then only to the address in your request, through your own curl. Your requests stay in the library file on your computer.
