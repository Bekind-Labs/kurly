Kurlyでできること

Kurlyは、curlコマンドを扱うためのデスクトップアプリです。curlコマンドとは、Web APIを呼び出す方法を1行で表したもので、APIのドキュメント、不具合報告、チャット、ブラウザーの開発者ツールなど、あらゆる場所で目にします。

curlは強力ですが、そのコマンドは読みにくく、間違えやすいものです。オプションは何十種類もあり、クォートにも気を使い、行も長くなりがちです。Kurlyはリクエストをひと目でわかるフォームにまとめ、編集に合わせて対応するコマンドを自動で更新します。たとえば次のような場面で使えます。

  • 作る：curlのオプションを覚えていなくてもコマンドを作成し、ターミナルやスクリプト、ドキュメントにコピーできます。
  • 読み解く：受け取ったコマンドをインポートすれば、URL・ヘッダー・ボディがフォームに整理されて表示されます。
  • 試す：リクエストを実行してレスポンスを確認できます。JSONやXMLは見やすくインデントされます。
  • 残す：よく使うリクエストをライブラリに保存しておけば、次回もすぐに呼び出せます。

KurlyはmacOS・Windows・Linuxで動作し、日本語と英語に対応した、無料のオープンソースソフトウェアです。

curlとは

curlは、サーバーにリクエストを送り、返ってきた内容を表示する無料のコマンドラインプログラムです。1998年から開発が続いており、多くのプロトコル（主にWebで使われるHTTPとHTTPS）に対応しています。macOS、Windows 10以降、そしてほとんどのLinuxに標準で入っているため、「APIの呼び出し方を正確に示す方法」として、curlコマンドが事実上の標準になっています。

Kurlyはcurlの代わりではありません。リクエストの実行にはパソコンに入っているcurlを使い、表示されるコマンドも、どこでも実行できる本物のcurlコマンドです。

リクエストとレスポンス

Web APIとのやりとりは、リクエストとレスポンスの会話です。リクエストで「何をしたいか」を伝え、サーバーはレスポンスで「どうなったか」を返します。

リクエストは次の要素からなります。

  • URL：送り先です。たとえばhttps://api.example.com/v1/users/42。?より後ろはクエリ文字列と呼ばれ、?page=2のような追加のパラメーターを表します。
  • メソッド：何をするか（下の表を参照）。
  • ヘッダー：名前: 値の形の追加情報です。受け取りたい形式（Accept: application/json）や認証情報（Authorization: Bearer …）などを伝えます。
  • ボディ：何かを作成・変更するときに送るデータです。JSONがよく使われます。
メソッド主な意味
GET取得する。省略時の既定値です。
POSTデータを送る。新しく作成するときによく使います。
PUT送ったデータで置き換える。
PATCH一部を変更する。
DELETE削除する。
HEADGETと同じですが、ボディなしでレスポンスヘッダーだけを受け取ります。
OPTIONSサーバーが何を許可しているかを問い合わせる。

レスポンスにはステータスコード、ヘッダー、そして多くの場合ボディが含まれます。ステータスコードの最初の数字で結果がわかります。2xxは成功（200 OK、201 Created）、3xxは別の場所へ（リダイレクト）、4xxはリクエスト側の問題（401 Unauthorized、404 Not Found）、5xxはサーバー側の問題です。

ポイント：curlにとっては、404や500のレスポンスでも「会話は成功」です。エラーになるのはサーバーとまったく通信できなかったときだけです。ただし-fオプション（Kurlyの「HTTPエラー時に失敗とする」）を付けると、4xx・5xxもエラーとして扱います。

curlコマンドの読み方

APIのドキュメントでよく見かける、典型的なコマンドの例です。

curl -X POST 'https://api.example.com/v1/users' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer YOUR_TOKEN' \
  --data-raw '{"name": "Hanako Yamada"}'
  • curlでプログラムを起動します。その後ろはすべてオプションとURLです。
  • -X POSTはメソッドの指定です。省略すると、curlはGET（ボディがあるときはPOST）を使います。そのためKurlyは、この場合-X POSTを省略します。
  • 'https://…/users'がURLです。
  • -Hごとにヘッダーが1つ追加されます。
  • --data-rawはボディで、書かれたとおりに送信されます。
  • 行末の\は「コマンドが次の行に続く」という意味です。
  • シングルクォート'…'で囲むと、&・?・$・空白などの文字をシェルが特別扱いしなくなります。値の中のシングルクォートは'\''と書きます。

多くのオプションには、-Hと--headerのように短い名前と長い名前があり、意味は同じです。Kurlyではどちらの形でも表示できます（コマンドを参照）。

よく使うオプション

よく使われるオプションと、Kurlyでの対応箇所です。

オプション働きKurlyでは
-X, --requestメソッドを指定するメソッド
-H, --headerヘッダーを追加するヘッダー
-d, --data, --data-rawボディを送る（リクエストはPOSTになる）リクエストボディ
-u, --userユーザー:パスワードでログインする（ベーシック認証）ユーザー
-A, --user-agentクライアントを名乗るUser-Agentヘッダーを指定するユーザーエージェント
-L, --locationリダイレクト（3xx）に従うリダイレクトに従う
-i, --includeボディの前にレスポンスヘッダーを表示するレスポンスヘッダーを含める
-I, --headヘッダーだけを要求する（HEAD）メソッド：HEAD
-v, --verbosecurlが送った内容も含め、やりとりをすべて表示する詳細出力
-s, --silent進行状況やエラーメッセージを表示しないサイレントモード
-f, --fail4xx・5xxのレスポンスをエラーとして扱うHTTPエラー時に失敗とする
--compressed圧縮されたレスポンスを要求し、展開する圧縮レスポンスを要求
-m, --max-time指定した秒数で打ち切るタイムアウト
-o, --outputレスポンスのボディをファイルに保存する出力をファイルに保存
-k, --insecureサーバーのセキュリティ証明書を検証しないTLS証明書の検証をスキップ

-kは慎重に。証明書の検証を省くと、本物のサーバーと通信しているか確かめられなくなります。自分の開発用サーバーでテストするときのためのもので、普段使いには向きません。

はじめに

インストール

ダウンロードから、お使いのシステム用のKurlyを入手してください。

  • macOS：.dmgを開き、Kurlyを「アプリケーション」にドラッグします（macOS 14.4以降のAppleシリコン搭載Mac）。初回は「開発元を確認できません」と表示されることがあります。その場合は「システム設定」→「プライバシーとセキュリティ」→「このまま開く」で許可してください。
  • Windows：.zipを展開してKurly.exeを実行するだけで、インストールは不要です。SmartScreenが表示された場合は「詳細情報」→「実行」を選んでください。
  • Linux：Flatpak版はflatpak install --user Kurly-*.flatpakでインストールします（必要なKDEランタイムはFlathubから自動で取得されます）。AppImage版はchmod +x Kurly-*.AppImageで実行権限を付けて起動します。Arch Linuxではパッケージとしてビルドすることもできます。

Kurlyはリクエストの実行にシステムのcurlを使います。curlはmacOS、Windows 10（バージョン1803）以降、そしてほとんどのLinuxディストリビューションに標準で入っています。

はじめてのリクエスト

  1. Kurlyを開き、URLにhttps://httpbin.org/getと入力します。httpbin.orgは、受け取ったリクエストの内容をそのまま返してくれる無料のテスト用サービスです。
  2. 右側のコマンドがcurl https://httpbin.org/getになります。
  3. 「実行」（Ctrl/⌘+Return）を押します。コマンドの下にレスポンスが表示され、状態欄には「完了」とかかった時間が表示されます。
  4. ヘッダーを追加して（たとえば名前X-Hello、値world）もう一度実行すると、httpbinの返答に追加したヘッダーが含まれます。

Kurlyの使い方

ウィンドウの構成

Kurlyのウィンドウは最大3つの列に分かれていて、境目はドラッグして幅を変えられます。

  • ライブラリ（任意・左側）：保存したリクエストの一覧です。「ライブラリ」をクリックするまでは表示されません。
  • フォーム（中央）：リクエストのすべての設定です。ウィンドウが小さいときはスクロールします。
  • コマンドとレスポンス（右側）：上にcurlコマンド、下に最後に実行したときのレスポンスが表示されます。

リクエストの作成

  • URLとメソッド：送り先と、何をするか（リクエストとレスポンスを参照）。HEADを選ぶと、curlの-Iオプションを使います。
  • ヘッダー：1行に1つずつ、名前と値を入力します。「ヘッダーを追加」で行を追加し、行を選んで「選択を削除」で削除します。名前が空の行は無視されます。
  • リクエストボディ：送信するデータです。入力したとおりに送られる（--data-raw）ので、application/jsonなどの対応するContent-Typeヘッダーと、ボディを送るメソッド（ふつうはPOST・PUT・PATCH）を忘れずに指定してください。
  • ユーザー：ベーシック認証を使うサーバー向けのユーザー:パスワードです。
  • ユーザーエージェント：curlが名乗る名前を置き換えます。
  • タイムアウト：何秒で打ち切るかを指定します。「なし」の場合は完了するまで待ちます。
  • 出力をファイルに保存：レスポンスのボディを画面に表示せず、ファイルに書き出します。Kurlyから実行した場合、out.jsonのような相対パスはホームフォルダーに保存されます（Flatpak版ではダウンロードフォルダー）。
  • オプション：よく使うcurlオプションのチェックボックスです。対応はよく使うオプションを参照してください。

コマンド

右上のコマンドは常にフォームの内容と一致しています。「コマンドをコピー」でクリップボードにコピーし、ターミナルやスクリプト、ドキュメントに貼り付けられます。次の2つのチェックボックスで、動作を変えずに書き方だけを変えられます。

  • 長いオプション名を使う：-Hの代わりに--headerと書きます。ドキュメントで読みやすくなります。
  • 複数行に分割：オプションを1行に1つずつ、\でつないで書きます。

どちらの設定も保持されます。コマンドはmacOSやLinuxのシェル（bash、zsh）向けにクォートされ、WindowsでもGit BashやWSLでそのまま使えます。PowerShellについては困ったときはを参照してください。

リクエストの実行

「実行」（Ctrl/⌘+Return。ボディの入力中でも使えます）を押すと、curlでリクエストを送信します。実行中はボタンが「停止」に変わります。

レスポンス欄には、curlが出力した内容がすべて表示されます。レスポンスのボディのほか、オプションをオンにしていればレスポンスヘッダーや詳細ログも表示されます。JSONやXMLのレスポンスを最後まで受け取ると、キーの順番を保ったままインデントして表示します。受け取ったままの形で見たいときは「JSON/XMLを整形」のチェックを外してください。非常に大きなレスポンスは約200万文字で打ち切られ、「[出力が長すぎるため省略しました]」と表示されます。その場合は「出力をファイルに保存」を使ってください。

状態欄には、実行がどう終わったかが表示されます。

表示意味
完了 · 153 ミリ秒curlがエラーなく終了しました（HTTPのステータスコードにかかわらず。上の説明を参照）。
curlが終了コード 6 で終了しました(ホスト名を解決できません)サーバー名が見つかりません。URLとインターネット接続を確認してください。
curlが終了コード 7 で終了しました(サーバーに接続できません)サーバーが接続を受け付けませんでした。サーバーが停止しているか、ポート番号が違う可能性があります。
curlが終了コード 22 で終了しました(HTTPエラーが返されました)「HTTPエラー時に失敗とする」がオンで、サーバーが4xx・5xxを返しました。
curlが終了コード 28 で終了しました(タイムアウトしました)タイムアウトの時間内に応答がありませんでした。
curlが終了コード 60 で終了しました(TLS証明書の問題)サーバーのセキュリティ証明書を検証できませんでした。
停止しました「停止」を押しました。
curlを起動できません。インストールされていて PATH に含まれているか確認してください。curlがインストールされていないか、見つかりません。困ったときはを参照してください。

そのほかの終了コードはcurlのドキュメントで説明されています。

コマンドのインポート

「curlコマンドをインポート…」（Ctrl/⌘+Shift+I）をクリックしてコマンドを貼り付けると、フォームに入力されます。クリップボードにcurlコマンドがあれば、あらかじめ入力されています。

ブラウザーが送ったリクエストをコピーするには、開発者ツール（F12、Macでは⌥+⌘+I）を開いて「ネットワーク」タブを表示し、ページを再読み込みしてから、リクエストを右クリックします。

  • Chrome・Edge：「コピー」→「cURL としてコピー（bash）」（Windowsでは「cURL としてコピー（cmd）」も可）。
  • Firefox：「値をコピー」→「cURL としてコピー」。
  • Safari：「cURLとしてコピー」。あらかじめSafariの設定の「詳細」で「Web開発者向け機能を表示」をオンにしてください。

bash形式とWindowsのcmd形式のどちらにも対応しています。インポート時に一部の内容は変換されます。-bで指定したCookieはCookieヘッダーに、-eはRefererヘッダーになり、--jsonはボディとJSON用のヘッダーになります。--proxyやファイルのアップロード（-F）など、Kurlyで表せないオプションはインポート後に一覧で表示され、取り込まれません。

ライブラリを開いているときは、インポートしたコマンドは新しいリクエストとして追加されます（現在のリクエストが空の場合を除く）。保存済みのリクエストが上書きされることはありません。ライブラリを閉じているときは、現在のリクエストが置き換えられます。

リクエストの保存

Kurly 0.2以降

Kurlyは作業内容を自動的に保存します。アプリを閉じても、次に開いたときにはリクエストがそのまま残っています。複数のリクエストを残しておくには、「ライブラリ」（Ctrl/⌘+B）をクリックして保存済みリクエストの一覧を表示します。リクエストをクリックすると開きます。リクエストごとにレスポンスが保持され、実行中のリクエストは、別のリクエストを見ている間もバックグラウンドで実行が続きます。

  • 「新規」（Ctrl/⌘+N）で空のリクエストを追加し、「複製」で選択中のリクエストをコピーします。
  • リクエストをダブルクリックするかF2を押すと、名前を変更できます。名前のないリクエストはGET api.example.com/v1/usersのようにメソッドとアドレスで表示されます。名前を消すと、この表示に戻ります。
  • 「削除」（またはDeleteキー。Macでは⌫）で、確認のうえ選択中のリクエストを削除します。
  • リクエストをドラッグして並べ替えられます。一覧の上の欄に入力すると、名前やURLで絞り込みができます。
  • リクエストを右クリックしても、同じ操作ができます。

ライブラリは、Kurlyのアプリデータ用フォルダーにあるlibrary.jsonというファイルに保存されます。

システムフォルダー
macOS~/Library/Application Support/Bekind Labs/Kurly/
Windows%APPDATA%\Bekind Labs\Kurly\
Linux~/.local/share/Bekind Labs/Kurly/
Linux（Flatpak版）~/.var/app/io.github.Bekind_Labs.Kurly/data/Bekind Labs/Kurly/

パスワードやトークンについて：Authorizationヘッダーやユーザーのパスワードなど、リクエストには認証情報が含まれることがあります。これらは、あなたのユーザーアカウントだけが読めるファイルに、平文で保存されます。パソコン上のファイルに置いておきたくない秘密情報は保存しないでください。

言語

Kurlyは、システムの言語が日本語なら日本語で、それ以外なら英語で起動します。右上の「言語」でいつでも切り替えられ、選んだ言語は次回も保持されます。

困ったときは

「curlを起動できません」と表示される
Kurlyがcurlプログラムを見つけられません。システムのパッケージマネージャーでインストールし（例：sudo apt install curl）、Kurlyを再起動してください。
macOSで「開けません」「確認できません」と表示される
KurlyはまだAppleの公証を受けていません。「システム設定」→「プライバシーとセキュリティ」を開き、Kurlyに関するメッセージの横の「このまま開く」をクリックしてください。一度許可すれば、次からは表示されません。
Windowsで「WindowsによってPCが保護されました」と表示される
「詳細情報」→「実行」を選んでください。SmartScreenは、まだあまり利用されていないアプリに対してこの表示を出します。
LinuxでAppImageが起動しない
実行権限があるか確認してください（chmod +x Kurly-*.AppImage）。また、AppImageにはFUSE 2が必要ですが、最近のUbuntuには標準では入っていません。libfuse2（Ubuntu 24.04ではlibfuse2t64）をインストールするか、--appimage-extract-and-runを付けて起動してください。
コピーしたコマンドがPowerShellで動かない
Windows PowerShellのcurlは別のコマンド（Invoke-WebRequestの別名）です。代わりにcurl.exeと入力してください。また、PowerShellでは\で行を続けられないため、「複数行に分割」はオフにしてください。いちばん手軽なのは、Git BashやWSLで実行する方法です。
プロキシ経由でリクエストを送りたい
curlはHTTPS_PROXYやNO_PROXYなどの標準的なプロキシ用環境変数を使います。Kurlyを起動する前にこれらを設定しておけば、Kurlyからのリクエストにも適用されます。
「ライブラリが破損しています」と表示される
library.jsonを読み込めなかったため、新しいライブラリを作成しました。元のファイルは同じ場所にlibrary.json.corrupt-…として残っているので、内容は失われていません。
「This plugin supports grabbing the mouse only for popup windows」と表示される
Waylandのデスクトップで、Qtがターミナルに出力する無害なメッセージです。問題はありません。

ほかにお困りのことがあれば、GitHubで問題を報告してください。

プライバシー

Kurlyにはアカウント登録もトラッキングもありません。ネットワークに接続するのはリクエストを実行したときだけで、接続先はリクエストに指定したアドレスのみ、使うのもあなたのcurlです。リクエストは、あなたのパソコン上のライブラリファイルに保存されます。
